1. 软件概览

QER (Quick Estimation of Reentry) 是一款用于卫星轨道预测与再入分析的桌面软件。 它基于 SGP4/SDP4 轨道传播器(Vallado 4.0 版本),支持对低轨目标进行批量筛选、陨落预报新算法（多 TLE 再入预测）、 传统算法（单 TLE 轨道外推与星历输出）,以及与 Fortran 版 ReentryProgram 的结果对比。

自 v3 版本起,QER 附带基于 Python 的 Web UI(web_ui.py), 提供可视化操作界面、运行结果图表化展示、CSV 导出等能力,无需手工编辑配置文件即可完成全流程操作。

2. 功能模块

QER 通过配置文件中的 function 字段切换不同功能,各功能模块如下:

0低轨目标筛选
按近地点高度阈值过滤 TLE 目录,输出符合条件的目标列表。
1TLE 质量评估ENABLED
对 TLE 数据进行质量评估（已临时打开，可在 Web UI 中选择并运行）。
2陨落预报新算法
批量处理多个 TLE 目标,预测各自的再入时间与位置（原名：多 TLE 再入预测）。
3传统算法
对单个 TLE 进行两阶段搜索(粗扫 10× 步长 + 精扫 1× 步长),输出再入结果与星历文件（原名：单 TLE 轨道预测）。
4再入结果对比
将 Function 3 的输出与 Fortran ReentryProgram 的输出进行对比分析。

3. 核心算法

3.1 SGP4/SDP4 轨道传播器

采用 Vallado 官方发布的 SGP4/SDP4 算法(版本 4.0)。对于近地目标(period < 225 min)使用 SGP4, 深空目标(period ≥ 225 min)使用 SDP4。算法基于 TLE 历元时刻进行轨道外推。

3.2 再入判定的内部阈值

程序内置常量 H_DECAY = 120 km:当传播过程中卫星高度低于 120 km 时, SGP4 传播器会停止工作并标记为"再入检测"。

⚠ 与用户阈值的关系
若用户配置的 reentryHeightKm 小于 120 km,传播器仍会在 120 km 处停止, 并以最后一个采样点作为近似再入点。详见 FAQ #1。

3.3 地球模型

位置矢量 vecr 的单位是米。高度计算公式: 

// 高度 = |vecr| - R_EARTH_M
double alt_m = sqrt(vecr[0]*vecr[0] + vecr[1]*vecr[1] + vecr[2]*vecr[2]);
double alt_km = (alt_m - 6378136.3) / 1000.0;

3.4 两阶段搜索策略(Function 3)

Function 3 采用两阶段搜索以兼顾精度与速度:

  1. 粗扫(Coarse):以 stepSec3 × 10 的步长大步推进,快速定位再入窗口。
  2. 精扫(Fine):在窗口内回退并以 stepSec3 × 1 的步长逐点推进,精化再入时刻。

每个采样点会在星历文件中以 coarse 或 fine 标识其所属阶段。

3.5 返回码约定

返回值含义
-1 再入检测:已到达阈值高度,使用最后一个采样点作为再入点。
0 真正的失败:传播异常退出,结果不可信。

/utf-8:同时将源字符集和执行字符集设为 UTF-8, 这是源代码中存在中文(注释、字符串字面量)时的关键设置,缺失会导致中文乱码。

  • SatSgp4.h
  • src/sim_input.cpp

4.4 GUI 编译步骤

  1. 打开 Visual Studio 2019,选择"打开项目/解决方案"。
  2. 定位到 QER.vcxproj 并打开。
  3. 在顶部工具栏选择配置 Debug | x64。
  4. 菜单栏 生成 → 生成解决方案(或按 Ctrl+Shift+B)。
  5. 编译成功后,可执行文件位于 x64/Debug/QER.exe。

4.5 命令行编译步骤

打开 "Developer Command Prompt for VS 2019",切换到 QER 目录后执行:

msbuild QER.vcxproj /p:Configuration=Debug /p:Platform=x64

编译产物路径:x64/Debug/QER.exe。

💡 提示
若需发布版,将 Configuration=Debug 改为 Configuration=Release 即可。

5. 配置文件格式 (QER.conf)

QER 通过 INI 风格的配置文件驱动。第一行 function 决定执行的功能, 其余参数按功能分组。注释以 # 开头。

5.1 完整示例

function = 3

# ============== Function 0 / 2 公共参数 ==============
tleFile0            = catalog-20250311-3line.tle
PerigeeHeightThreshold = 300.0
outFile0            = test/out_fun0.txt
objectType          = all

# ============== Function 3 参数 ==============
tleFile3          = input/test_decay.tle
forecastDays3     = 5.0
stepSec3          = 60.0
reentryHeightKm   = 80.0
outFile3          = test/out_fun3.txt
outEphFile3       = test/out_fun3.eph

# ============== Function 4 参数 ==============
reentryFileA = test/out_fun3.txt
reentryFileB = ../BCbyTLE/ReentryProgram/files/21retimes-last.txt
outFile4     = test/out_fun4.txt

5.2 参数说明

Function 0 / 2 共用参数

参数类型说明
tleFile0路径TLE 目录文件(3 行格式)
PerigeeHeightThresholddouble, km近地点高度阈值,Function 0 用此值筛选
outFile0路径筛选结果输出文件
objectType枚举目标类型过滤,可取 all / 其他

Function 3 参数

参数类型说明
tleFile3路径单目标 TLE 文件
forecastDays3double, day预测时长(天)
stepSec3double, s基础步长(秒),粗扫时为 ×10
reentryHeightKmdouble, km用户指定的再入高度阈值(下限受 120km 限制)
outFile3路径再入结果输出文件
outEphFile3路径星历输出文件

Function 4 参数

参数类型说明
reentryFileA路径方法 A 输出(Function 3 结果文件)
reentryFileB路径方法 B 输出(Fortran ReentryProgram 结果文件)
outFile4路径对比结果输出文件

7. 输出文件格式

7.1 out_fun3.txt(再入结果)

Tab 或空格分隔,每行一个目标,字段顺序如下:

#列名单位/格式说明
1objID字符串目标标识(NORAD 编号或名称)
2mjdEpochMJDTLE 历元时刻(修正儒略日)
3mjdReentryMJD预测再入时刻
4reentryDateUTC再入时刻(UTC 字符串)
5lifeDaysday剩余寿命 = mjdReentry − mjdEpoch
6latdeg再入点地心纬度(≈地理纬度)
7londegECI 赤经(非地理经度)
8altkm再入点高度(≈120km 或用户阈值)

7.2 out_fun3.eph(星历文件)

每个目标一个段落,格式如下:

# 目标头:objID / 历元 MJD / 再入 MJD / 剩余寿命
# objID: XXXXX mjdEpoch: XXX mjdReentry: XXX lifeDays: XXX

# 数据列:mjd, alt(km), phase(coarse/fine)
60532.000000  350.123  coarse
60532.000694  349.876  coarse
...
60533.012345  120.456  fine

7.3 out_fun4.txt(对比结果)

文件由以下若干段组成:

  1. 文件来源说明:列出方法 A、方法 B 的输入文件路径。
  2. B 方法统计摘要:对每个 TLE 历元的 10 个 BC 值给出统计。
  3. 逐目标对比:方法 A 与方法 B(均值/范围)的并排对比。
  4. 差异统计:整体差异的均值、最大、最小、标准差等。
  5. 总体结论:对方法 A 与方法 B 偏差程度的总结性评述。

10. 重要注意事项

ℹ 单位与坐标
  • vecr 的单位是米,高度计算使用 R_EARTH_M = 6378136.3 m。
  • lat 是地心纬度(≈地理纬度);lon 是 ECI 赤经,非地理经度。
⚠ 返回码
  • PropTleOrbit_ECIRecord 返回 -1 表示再入检测(使用最后一个采样点)。
  • 返回 0 表示真正的失败,结果不可信。
⚠ 120 km 阈值限制
若用户配置的 reentryHeightKm < 120 km(SGP4 内部阈值), 传播器仍会在 120 km 处停止,并以最后一个采样点作为近似再入点。 因此 out_fun3.txt 中的高度可能显示为 ~120 km 而非用户设定的 80 km。
💡 两阶段搜索(Function 3)
Function 3 采用两阶段搜索:
  • 粗扫(Coarse):stepSec3 × 10 大步推进,定位再入窗口。
  • 精扫(Fine):stepSec3 × 1 小步推进,精化再入时刻。

11. 常见问题(FAQ)

Q1:为什么高度显示为 ~120 km 而非配置的 80 km?
A:SGP4 内部有一个 120 km 的硬阈值。当用户设定的 reentryHeightKm < 120 km 时, 传播器会在 120 km 处停止,并以最后一个采样点作为近似再入点。因此输出高度显示约为 120 km。
Q2:为什么方法 A(Function 3)的再入时间比方法 B 晚?
A:Function 3(方法 A)使用 SGP4 传播器但未引入大气模型; 而 ReentryProgram(方法 B)使用多 BC + NRLMSISE-00 大气模型, 能更准确地预测较快衰减,因此预测的再入时间更早。
Q3:如何理解方法 B 的 MJD 范围虚线?
A:每个方法 B 再入点对应 10 个 BC(弹道系数)值, 会产生一个再入时刻范围。图中的虚线即表示该范围的 min–max 边界。
Q4:Web 服务器无法启动?
A:请检查端口 8080 是否已被占用。可改用其他端口: python web_ui.py 8081。
Q5:图表无法渲染?
A:Plotly.js 通过 CDN 加载,需保证网络畅通。请打开浏览器控制台查看具体错误。
